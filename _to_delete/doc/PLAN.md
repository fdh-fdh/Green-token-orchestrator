# GreenPulse 门禁式执行计划

飞书「2026 AI 先锋未来人才大赛」世纪互联赛道。撰写日期 2026-07-29。

本计划继承姊妹项目(Huawei Tech Arena, Topic 2)的方法论:**活动式清单("实现 X")不构成计划**——"实现 X"可以被报告为完成,而 X 本应保证的性质仍然为假。因此每个阶段都以**准入/准出判据**定义,判据是评审者无需咨询作者意图即可判定的量;判据未满足,阶段不交接。**所有阶段(含 P0、A、R,不只命名了 Gate 的 S/O)的准出判据表都由独立评审代理按 [`REVIEW_AGENT.md`](REVIEW_AGENT.md) 章程做阻塞式验收。**配套文件:[`IDEA_REVIEW.md`](IDEA_REVIEW.md)(为什么是这些阶段)、[`RISKS.md`](RISKS.md)(什么会打断计划,以及止损日期)、[`ENGINEERING_RULES.md`](ENGINEERING_RULES.md)(如何证明做到了)。

## 1. 依赖链(顺序不可协商的原因)

```
评测协议(基线+口径+指标) → 实验记录 → 收益对照表 → 答辩材料(报告/PPT/Demo)
        │                                                    ▲
        ├──→ 上限分析(oracle) ──→ 叙事定型 ────────────────────┤
        │                                                    │
        └──→ 仿真环境 ──→ 调度器与 token 旋钮 ──→ 适配层+大屏 ──┘
```

- 答辩材料里的每个数字都必须来自固定协议下的实验记录;协议冻结后每改一次,此前所有记录作废重跑。**协议每晚一天,答辩材料就晚一天,且晚在最没有余量的末端。**
- **上限分析在调度器之前**:oracle 在目标电网曲线下最多省多少,决定整个项目的叙事(节碳工具 vs 绿电消纳工具 vs 峰值/成本工具)。答辩前才发现上限只有 8%,是本计划要排除的最大灾难(依据:EuroSys 2024 上限研究,[`IDEA_REVIEW.md`](IDEA_REVIEW.md) Q2.5)。
- 大屏与适配层在链的末端:它们消费数字,不生产证据。三人队最容易犯的错是先做大屏。

**目的:让一个数字有含义。** 本阶段冻结的协议是此后一切实验记录的前提([`RISKS.md`](RISKS.md) R5)。

## 4. Stage O — 调度器与 token 旋钮

**目的:改进一个已经有含义的数字。**

### 准入判据

- O-E1. Gate S 通过,协议冻结。
- O-E2. 基线全家桶已在协议下跑通并留痕(它们同时是调度器的对照组)。

### 准出判据

| # | 判据 | 判定方式 |
|---|---|---|
| O-X1 | 滚动时域调度器(MILP 或启发式,开源求解器)实现 README 五项加权目标(**ε 迁移/重启成本项在 MVP 以固定惩罚常量近似,不建模真实中断-恢复语义;此近似写进协议**),权重扫参报 **Pareto 前沿**而非单点 | 协议下与全部基线对照;每个宣称的改进 > 双跑波动带 |
| O-X2 | **token 级旋钮至少一个落地**(默认:碳感知模型路由,参照 GAR 的可行集+约束优化框架;扩展:Sprout 式 token 预算指令) | 等质量约束下(质量指标与阈值在协议里预注册)报告 gCO2/token 下降;质量、时延、碳三者同表呈现 |
| O-X3 | 双口径纪律执行:每个节碳结论平均/边际并列;两口径矛盾时如实呈现矛盾 | 抽查任意结果表 |
| O-X4 | 预测误差敏感性(**压缩版**):对绿电/碳强度预测注入至少一组定量噪声,报告该水平下的收益衰减;完整衰减曲线记为 08-16 后回收项 | `results/` 有敏感性实验记录 |
| O-X5 | SLA 保底证明:刚性任务的 SLO 达成率在所有实验中不低于 carbon-agnostic 基线;`ecoModeOff` 开关有测试 | 逐实验检查;开关关闭时行为与基线 bit 级一致 |

### Gate O

## 7. 本计划明确不承诺的事

- **不承诺击败任何论文的公开数字。** 跨口径比较被 R-X4 禁止;我们承诺的是自家协议下相对自家基线的、双口径的收益。
- **不承诺 RL/学习型调度器。** 上限研究表明简单策略拿走大部分收益;MVP 用 MILP/启发式,学习型方法是 Stage O 通过后的可选实验。
- **不承诺接入真实集群与真实电力数据。** MVP 是 Digital Twin(README 自己的定位);接口为真实化留门(SiL,参照 Vessim),但 P0-X4 探明结果决定真实数据是否进入本届交付。
- **不承诺五个旋钮全部实现。** when/where(调度)+ which-model(路由)三个进 MVP;how(功率封顶)与 how-many-tokens(生成指令)记录为扩展路线并在报告中引用出处。
- **不承诺任务中断-恢复(preempt-resume)语义与周级功能。** README 任务画像中的"可中断性"在 MVP 只作为布尔约束(不可中断任务不得被重排出已分配窗口),ε 迁移/重启成本以固定惩罚常量近似(O-X1);README 的"周级扩展"(容量规划、绿电采购、储能策略、任务预约)整体 SKIPPED,理由:与 MVP 的验证目标(调度收益可量化)无关,且各自是独立的大命题。
