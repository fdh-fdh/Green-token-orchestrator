# GreenPulse 工程设计规则(长期遵守)

本文件是**内部可执行规则**,回答"我们必须怎么做、以及机器如何证明我们做到了";外部对标与调研结论在 [`DESIGN_STANDARDS.md`](DESIGN_STANDARDS.md)。

本项目零代码起步,没有自己的事故史,因此每条规则标注的事故来自**姊妹项目**(Huawei Tech Arena 电力韧性预测,同团队,2026-07)——那套仓库用三个月踩出的坑,本项目从第一行代码起就必须免疫。规则若与姊妹项目相同,只写结论与事故摘要;GreenPulse 特有的规则(§1.5 起、§3)写全。

## 0. 第一原则

> **规则若没有执行点,就只是愿望;执行点若不是机器,必须承认它更弱。**

每条规则必须绑定执行点;**能机器验证的必须机器验证(CI 检查、测试),做不到的显式标注为人工评审项**——人工项是承认的妥协,不是默认选项。没有任何执行点的条目不写进本文件。

**优先级**:**大赛硬性条款(提交格式、原创性、许可要求、截止时间)> 用户明确指令 > 本文件 > 通用最佳实践**。大赛规则与本文件冲突时无条件让位并在此记录例外——参赛项目违反赛规即失格,任何工程洁癖都不值这个代价。

### R0.1 检查本身必须正向断言,且 fail-closed

判定条件写成正向断言(必须明确满足才放行);禁止对自由文本做子串匹配判定;检查器自身要有反例测试。
**姊妹项目事故**:并发检测判定 `if (/CONCURRENT WRITER/i.test(...))`,而正常输出是 `CLEAR — No concurrent writer detected`——否定句里含被匹配子串,一切正常时反而中止。

### R0.2 新增测试必须先在未修复代码上证明为红

绿色测试本身不构成证据——只有"先红后绿"构成证据。断言必须落在被判定的量本身:测行数不等于测分布,测顶层键不等于测配置生效,测均值有序不等于测逐样本有序。
**姊妹项目事故**:四个独立的绿色测试文件同时为已损坏的行为背书(config 层算术测试放过了 11.8 倍笛卡尔扇出;行数断言放过了目标分布漂移到 80% 高风险区;顶层键检查放过了嵌套死配置;均值有序断言背书了"逐场景严格有序"的 README 声明,实际逐场景只有 2.7% 成立)。四者共同点:**断言的对象比声称的保证低一个层级。**
**执行点**:每个新增测试必须附"在未修复代码上 FAIL"的输出,否则评审不接收。

**GreenPulse 的高危对应物(预先点名)**:(a) 断言"调度器输出了计划"不等于断言"计划满足 SLA 且降碳"——必须断言指标本身;(b) 断言"碳强度曲线加载成功"不等于断言"调度器消费的是这条曲线而非默认常量";(c) 断言"节碳 x%"必须绑定口径(平均/边际)与基线名,无口径的节碳断言禁止出现在测试名与文档里。

## 1. 架构原则(不可协商)

### R1.1 配置是唯一真源

所有超参数、阈值、路径、时间尺度、目标函数权重(α-ε)、Pod/园区定义、信号源选择必须来自单一 YAML,经加载器校验为冻结对象。代码中不得出现这些值的字面量;YAML 中不得存在无人消费的键。
**姊妹项目事故**:config.yaml 存在但从未被加载,且值已漂移(声明 0.5,实际训练用 0.05)。
**执行点**:配置消费测试(逐**叶子键**匹配,不是顶层键——姊妹项目在这里栽过第二次);反向魔数扫描。

### R1.2 数据与信号访问走接口,实现可替换

碳强度、绿电预测、电价、负载 trace、集群状态全部走抽象接口 + 注册表按名选择。业务逻辑不 import 具体实现、不按源名分支。**实时值与预报是两个接口**(不假设 Provider 两者都有——GSF Carbon Aware SDK 的教训性设计)。
**验收标准:接一个新 Provider = 新增 1 个文件 + 1 行配置,改动 0 个下游文件。** 首个新源接入时用 `git diff --stat` 实际验收(姊妹项目直到最后也没真正演练过这条,引以为戒)。
**执行点**:注册表测试 + 契约测试(不满足 schema 的 Provider 被拒绝并报可读错误)。

### R1.3 合成数据是一个 Provider,不是特例分支

合成绿电曲线、合成任务流与真实数据实现同一接口、单独成模块。**MVP 以合成为主不是降低此规则的理由,而是提高**:全项目最重要的对外声明("降碳 x%")在 MVP 期完全建立在合成 Provider 上,它必须与未来真实 Provider 完全同构,数字才有被真实数据替换后仍可比的可能。
**姊妹项目事故**:`--mode real` 只 print 一句就退回合成数据——一旦合成是 if 分支而非同接口 Provider,真实通路就缺乏演练,腐烂到需要时才发现。
**执行点**:合成 Provider 与真实 Provider 通过**同一套契约测试**(schema、溯源标记、分辨率校验);契约测试对 Provider 类型无感知。

### R1.4 禁止供应商/地域/存储假设泄漏进通用代码

- 通用模块不得出现 Electricity Maps/WattTime 的专有字段名、区域编码;规范化(统一为 gCO2/kWh、UTC 时间戳、`site_id`)只发生在对应适配器内。
- **不与数据库过拟合(本项目的明文要求)**:MVP 的持久化只允许通过一个薄存储接口(读写实验记录、决策记录、曲线快照);默认实现用文件(CSV/Parquet/SQLite 单文件),接口设计以"换成 PostgreSQL/时序库/对象存储不改调用方"为验收。**禁止在业务代码中出现任何 SQL 方言、ORM 模型或特定数据库连接串**;禁止把调度逻辑写进存储过程/物化视图。
- 对外暴露一律走中性介质:Prometheus 指标(前缀 `gto_`)、K8s ConfigMap 契约、OpenAI 兼容 API(路由场景)——消费者不知道上游是谁(参照 Azure carbon-intensity-exporter → KEDA operator 的解耦范式)。

**执行点**:CI 可移植性扫描——`src/` 命中具体供应商字段名、SQL 方言关键字、硬编码区域/路径即 fail;适配器目录显式豁免且豁免表每次运行打印。

### R1.5 物理量语义显式推导,单位在边界处统一

- 时间:所有窗口/地平线以物理时间(分钟/小时)声明,步数由分辨率推导,除不尽即报错(姊妹项目 R1.5 原样继承)。
- 能量与碳:内部统一 J、kWh、gCO2;`gCO2/token` 的分母必须明确 token 计法(输入+输出?仅输出?)并全库唯一;**碳强度值必须携带口径标签(average/marginal)与来源**,无标签的碳强度值在类型上就不可构造。
- 功率与能量不得混用(kW vs kWh):字段名后缀强制(`_kw` / `_kwh` / `_gco2_per_kwh`)。

**执行点**:单位后缀 lint(自写脚本);口径标签为枚举类型,序列化测试。

### R1.6 不可变数据流;调度决策可解释、可重放

不修改调用方传入对象。每个调度决策落一条结构化记录:任务、动作、时窗、**决策时刻的信号快照**、目标函数各项贡献值。给定同一快照与 config,决策必须可确定性重放。
**理由(GreenPulse 特有)**:本项目的可信性建立在"为什么把任务挪到 12:00"可以被逐项拆账;不可重放的调度器在答辩里等于黑盒。
**执行点**:决策重放测试(快照进,决策出,双跑一致)。

## 2. 质量门禁(CI 强制,不通过不得合入)

| 门禁 | 阈值/规则 | 执行方式 |
|---|---|---|
| 静态检查 | ruff 零告警(Python);golangci-lint(若有 Go 适配器) | CI |
| 测试 | 全绿;新测试附红证 | CI + 评审清单 |
| 覆盖率 | **先测量,后设门**:首个里程碑实测三次取整减 2 设为门禁,只升不降(棘轮)。禁止未测量就写一个好看的数字 | `pytest --cov --cov-fail-under=N` |
| 依赖可复现 | 精确锁定;只锁实际 import 的包 | 干净环境安装 + CI 复跑 |
| 可移植性 | R1.4 扫描 | CI 脚本 |
| 配置一致性 | 无死配置叶子键;无未经配置的魔数 | 配置消费测试 |
| 确定性 | 同 seed 仿真双跑 bit 级一致;求解器线程数显式 | 双跑对比测试 |
| 发布一致性 | tag、CHANGELOG、版本号三处一致;版本不得旧于已有 tag | 发布元数据测试(姊妹项目 v0.6.0 三处三答案事故的现成解药) |

**豁免纪律**:豁免的第一选择是消灭豁免的理由;当前豁免清单必须在本节维护且与配置同步,唯一自带过期机制的豁免形状是 strict xfail(缺陷未修但所需行为已断言,修好即强制摘标)。

## 3. 度量与声明纪律(本项目的命门)

### R3.1 每个节碳/节费声明必须携带四件套

**口径(average/marginal)、基线名、负载与信号数据版本、SLO 代价。** 四缺一的数字禁止出现在 README、报告、PPT、commit message。规则同等覆盖**节费/成本**声明(成本无口径问题,其余三件照套)。
**依据**:e-Energy 2024 实测 65 个电网区域中 55.4% 平均/边际信号负相关——换口径结论可以翻转(**该数字的确切口径在 P0-X4 复核原文后回填**);只报碳降不报 SLO 代价的结果在本领域评审中直接不可信。
**执行点**:文档 lint 扫描 `%` 与"碳/carbon/费/成本/cost"共现的行,**四要素齐验**——同段须命中口径关键词(average/marginal/平均/边际,成本类豁免此项)、基线名(与协议基线集名单匹配)、数据版本标识、SLO/质量代价关键词;lint 对新增文档行 fail-closed。lint 覆盖不了的表述变体由评审清单兜底(显式承认的人工项)。

### R3.2 数据性质标注

每张图、每个表、每个指标标注 synthetic / real / derived-from-real(如从 Azure trace 派生)。合成收益旁必须有"合成场景,非实测"。README 现存的 `"expected_carbon_reduction": "28%"` 类示例值,一律改为明示占位。
**姊妹项目事故**:完美预报特征把 0.816 报成性能,实为上界。GreenPulse 的直接对应物:**oracle 上限数字被当成产品收益引用**——上限分析(PLAN S-X3)的产出必须永远带 "oracle 上界" 前缀。

### R3.3 禁止跨口径比较

不与 GAR/CarbonScaler/CASPER 等论文的节碳%并列比较(电网、负载、口径、SLO 全不同);**对外材料中的**相关工作对照表只对比**机制与视角**,不对比数字。内部文档为校准水位线可以罗列论文数字,但必须带"禁止进入对外对照表"的脚注(见 DESIGN_STANDARDS §2.1)。
**姊妹项目事故**:自家 38.2% 的 MdAPE 差点与 Cerrai 的 59% 并列——口径不同的"更好"是错误结论。
**执行点**:文档 lint 扫描对外材料目录(`reports/`、README)中论文名/引用与 `%` 数字的同行共现,命中即 fail;内部 docs/ 目录豁免但检查脚注存在。

### R3.4 每次实验留痕

指标与 git SHA、dirty 标志、config hash、**协议版本**一同落盘;收益对照表由记录透视,不得手工誊抄;答辩材料里的数字必须能反查到行。dirty 树产出的行不得进入对外材料(姊妹项目 58 行全 dirty 的教训)。

### R3.5 必须有基线全家桶

carbon-agnostic 性能最优 / 最优静态 / Price-only / Carbon-only / oracle。任何"GreenPulse 更好"的表述都是相对这五者中明确的一个。
**依据**:强论文的共同做法(CarbonScaler 对最优静态只 +8%,GAR 报"达 oracle 97%"——诚实的数字长这样);FIFO 单基线是稻草人对照。
**执行点**:评测入口在产出任何对照表前断言实验记录中五基线在当前协议版本下记录齐全,缺任一即拒绝生成。

## 4. DFX 准出清单

- **DFR 可靠性**:每个外部依赖有明确失效行为并有故障注入测试;**信号断供时降级为 carbon-agnostic 并显式告警,绝不拿过期/编造的碳强度继续"绿色"调度**(完整矩阵见 [`DFR.md`](DFR.md))。
- **DFT 可测试性**:核心不变量(SLA 保底、决策可重放、口径标签)有守护测试;全链路可在无外网、无 GPU、无 K8s 条件下用 mock Provider 跑通(这同时是 demo 的复现路径)。
- **DFD 可部署性**:`make demo` 一条命令从零到出图;运行时与硬件披露;指标给容差。
- **DFS 可服务性**:分级日志;`ecoModeOff` 逃生开关;决策记录即审计日志。

> **本项目的特殊要求**:我们向别人售卖"把负载调到更绿的时刻"的可信度。自己的数字口径不干净,是立场性缺陷,不只是工程债。

## 5. 可信与合规

- 数据与依赖许可逐源记录([`DATA_LICENSES.md`](DATA_LICENSES.md));**AGPL 代码(electricitymaps-contrib)零 vendor**,只走 API 边界;受商业条款约束的数据快照不入库。
- 密钥走环境变量,仓库提供 `.env.example`;mock Provider 保证无密钥可跑 CI 与 demo。
- 引用必须打开链接核实到一手来源;转述他人核查结论标注为待核实。(姊妹项目一次核查 30 条引用错 4 条、归属错 6 条。)

## 6. 变更与基线管理

特性分支 + 逻辑化提交;里程碑 annotated tag 与 CHANGELOG 对齐(发布元数据测试强制);可再生产物(计划、曲线、图)不入库,实验记录入库;评测协议冻结后按 [`RISKS.md`](RISKS.md) §2 的 fatal-defect 流程管理变更;死代码即缺陷。

## 附:本文件的维护规则

新增规则必须附真实事故(自己的或姊妹项目的,注明出处)与执行点,缺一不写;规则失效标注废止原因而非删除;每个 Gate 复盘:哪条规则拦住了缺陷、哪条形同虚设。
