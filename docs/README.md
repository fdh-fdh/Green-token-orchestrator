# docs/ 文档导读

本目录是 GreenPulse 的**项目治理文档集**:它们不描述代码怎么写(那在代码与代码注释里),而是回答四个更根本的问题——**为什么做这个方案、按什么顺序做、怎么证明做到了、什么情况下止损**。全部文档撰写/定稿于 2026-07-29,配合硬截止 2026-08-16 的大赛日历使用。

## 编号系统速查

文档间大量交叉引用依靠一套稳定编号,规则如下(编号一旦分配不回收、不重排,被砍的项保留编号并标 SKIPPED):

**阶段判据(PLAN.md):`阶段-类型序号`**

- 阶段:**P0** 奠基 / **S** 仿真与协议 / **O** 调度优化 / **A** 适配与演示 / **R** 交付
- 类型:**X** = eXit 准出判据(做完什么才能离开该阶段);**E** = Entry 准入判据(满足什么才允许开工)
- 例:`P0-X1` = P0 第 1 条准出判据(仓库骨架);`S-E2` = Stage S 第 2 条准入判据

**风险(RISKS.md):`R1`–`R10`**,按登记顺序,已关闭的风险编号仍保留。

**工程规则(ENGINEERING_RULES.md):`R章.条`**

- R0.x 元规则(关于检查本身,如 R0.2 先红后绿)
- R1.x 架构原则(R1.1 配置唯一真源、R1.2 接口化、R1.5 单位与口径显式…)
- R3.x 声明纪律(R3.1 数字四件套、R3.2 数据性质标注、R3.5 五基线全家桶…)
- ⚠️ 与 RISKS 的 R 是两个体系:带小数点(`R3.1`)是工程规则,不带(`R3`)且在风险语境里是风险条目

**失效契约(DFR.md):`DEP-依赖组.失效模式`**

- DEP-1 信号 Provider / DEP-2 负载 trace / DEP-3 合成生成器 / DEP-4 仿真内核 / DEP-5 求解器 / DEP-6 配置 / DEP-7 执行适配器 / DEP-8 运行产物
- 例:`DEP-4.4` = 仿真内核的"前视泄漏"(调度器偷看未来信号)——代码中测试名直接引用,如 `test_dep_4_4_lookahead_rejected`

**评审 findings(REVIEW_AGENT.md / 2026-07-29-docset.md):`F/M/N-序号`** = Fatal / Major / miNor + 发现顺序。

## 关键概念小词典

读这套文档会反复遇到以下术语:

- **门禁式计划**:每个阶段用"评审者无需咨询作者即可判定"的判据定义,判据不满足阶段不交接。区别于"实现 X"式活动清单——后者可以被报告为完成,而 X 本应保证的性质仍然为假。
- **数字四件套**:任何节碳/节费声明必须同时携带 ① 口径(平均/边际)② 基线名 ③ 数据版本 ④ SLO 代价。四缺一的数字禁止出现在任何材料里。
- **双口径**:电网碳强度有平均(average)与边际(marginal)两种算法,实证研究显示大量电网区域两者负相关——**换口径结论可以翻转**,所以每个节碳结论都要双口径并列。
- **oracle 上界**:用"事后完美预测"跑出的最好成绩。它回答"这个电网曲线下理论上最多省多少",用于校准叙事;**永远不是产品收益**,引用必须带"oracle 上界"前缀。
- **上限分析**:项目排在调度器开发之前的第一个实验(S-X3)。若上限只有个位数百分比,主叙事提前从"节碳"切换为"绿电消纳/成本",避免答辩现场被证伪。
- **止损日**:每条风险预设的"无论是否解除、当天启用预案"的日期。没有止损日的风险不叫被管理,叫等着被发现。
- **冻结**:三级——评测协议冻结(Gate S,改一项则此前实验记录全部作废)、功能冻结(08-14)、材料冻结(08-15)。冻结后只接受 fatal-defect 类变更。
- **先红后绿(R0.2)**:新增测试必须先在未修复的代码上证明会失败(红),才能作为证据。绿色测试本身不构成证据——姊妹项目曾四次发生"绿色测试为坏行为背书"。
- **断言层级**:测试断言的量必须与声称保证的量同级。"断言输出了计划"≠"断言计划满足 SLA 且降碳";"断言曲线加载成功"≠"断言调度器消费了这条曲线"。
- **PINNED / strict xfail**:DFR 矩阵中,所需行为已实现并有测试守护的格子标 PINNED;尚未实现的用 strict xfail 挂账——一旦行为实现,xfail 测试会转为意外通过而强制报错,逼你摘标。这是唯一自带过期机制的豁免形状。
- **前视泄漏**:调度器读到了决策时刻之后的信号——本项目版本的"数据泄漏",会让收益不劳而获,由 DEP-4.4 守护测试封死。
- **姊妹项目**:同团队 2026-07 的华为比赛项目(电力韧性预测)。本文档集的方法论、多数规则及其事故案例都继承自它——GreenPulse 从第一行代码起就要对那些坑免疫。

## 推荐阅读顺序

**新加入的队员**(约 1 小时):
`COMPETITION_BRIEF` → `PLAN`(重点 §0/§1/§6 日历)→ `ENGINEERING_RULES`(重点 §0/§1/§3)→ 其余按需。

**要写代码了**:
`ENGINEERING_RULES` 全文 → `DFR` 中你要碰的 DEP 分组 → `PLAN` 当前阶段的判据表。

**要引入外部数据/依赖**:
先查 `DATA_LICENSES` 总表有没有这一行;没有就先加行再引入(RISKS R9 的 Trigger 就是"引入了但没记录")。

**要做 Gate 评审**:
`REVIEW_AGENT` 全文(§5 有可直接使用的评审代理提示词)→ 被评审阶段在 `PLAN` 的判据表 → `2026-07-29-docset.md` 看 findings 的格式先例。

**评委/外部读者想快速理解项目**:
仓库根目录的 `README.md`(demo 导向)→ `COMPETITION_BRIEF` 的覆盖映射表 → `PLAN` §7"明确不承诺的事"(了解边界)。

## 维护约定

- 文档与树必须一致:状态标注(DONE/PARTIAL/PLANNED/SKIPPED)每个 Gate 双向复核——假 DONE 与假 PLANNED 同罪。
- 编号只增不改;砍掉的项保留编号并标 SKIPPED 附理由。
- 外部事实引用须可打开的一手来源;转述他人核查结论一律标"待核实"。
- 本目录新增评审记录统一放 `reviews/<日期>-<gate>.md`(格式见 REVIEW_AGENT §4)。
